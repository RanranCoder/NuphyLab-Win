# NuPhyLab Bug 审计报告（Windows 移植前基线）

日期：2026-10-24 · 基线：v1.0.11 · 方法：四个独立审计通道（server 核心 / 集成与输入 / shared 逻辑 / UI + Swift 原生层）逐行阅读 + 本机 Windows 实测 + 关键发现人工复核。所有结论已与 docs/ 下 QA 文档交叉核对，文档记载的"有意行为"不计入。

## 0. 总体结论

- **无 P0**。代码整体质量高：并发骨架（busy 互斥 + 请求串行 + 捕获即备份）、HTTP token/Host/Origin 防线、fs 原子写、S4 协议边界检查均经得起推敲。
- **2 个 P1**：均在 native/macOS 侧或 macOS 专属进程探测逻辑，不阻塞移植，但定义了 Rust 重写时必须避免的模式。
- **5 个 P2**：其中 3 个位于移植会原样保留的跨平台代码中，建议在移植过程中一并修复（修复清单见 §3）。
- **Windows 实测基线**：`npm test` 324 用例，186 过 / 136 挂 / 2 跳过。**136 个失败全部同源**（测试夹具的平台问题，见 §1），无真实逻辑测试失败。

## 2. 发现清单

### P1（2 项）

**[P1] native/AppHost.swift:158-159 — worker stdout 管道 EOF 后 readabilityHandler 死循环空转 CPU**（已复核确认）
- stderr 处理器（:152-156）在 `data.isEmpty` 时正确置 `readabilityHandler=nil`，stdout 处理器只 `return`；`terminationHandler`（:164-176）也只清理 stderr 管道。worker 退出后 stdout 永久可读 EOF，handler 被无限重入，烧满单核直到用户手动退出。
- 处置：macOS 专属；**Rust 壳的 stdout 读循环按 EOF 终止语义重写**，勿复制该模式。

**[P1] server/claude-sessions.mjs:33-37 — `ps` 部分成功时丢弃全部 pid 存活证据**（代码逻辑确认；BSD ps 退出码行为需 macOS 实机复核）
- catch 块把"非零退出 + 空 stdout"当作全部死亡，"非零退出 + 非空 stdout"返回 `null`。BSD ps 在 `-p` 列表任一 pid 不存在时即非零退出且照常输出存活行 → 只要混入一个死 pid，`resolveLiveness` 全部返回 `alive:null`，死会话灯效最长错显 6 小时（staleMs 默认值）。对比同仓库 `codex-writers.mjs:18-20` 对 lsof 的部分成功做了正确处理。
- 处置：macOS 专属逻辑；Windows 重写（PowerShell CIM / `Get-Process`）时**必须处理部分匹配输出**，勿复制该 catch 语义。

### P2（5 项）

**[P2] server/main.mjs:668-676 — 手动 `connect` 的恢复编排与自动重连（:410-431）不一致，播放中动画可被静默丢弃**（确认）
- 自动重连含 `playback.playing → activate()` 分支；手动 connect 缺失，且在 `codexEnabled/claudeEnabled` 时走 `startAgentLighting()` 内部清空 `suspendedScene/pendingSceneRestore` 并接管。拔线→插回自动恢复播放；同一状态点"连接"按钮则动画被 agent 灯光抢占。属跨平台逻辑，随移植保留。

**[P2] native/AppHost.swift:365-375（配合 AudioCapture.swift:107-108）— 一次失败的 /api/state 轮询被当作"禁用"配置**（路径确认，触发频率需运行验证）
- 非 200/超时都得到 `keys=nil` → 注销全部 Carbon 热键 + 停掉音频采集（拆聚合设备），0.5s 后自愈重建。服务端被慢 HID 交换阻塞 >3s 即出现快捷键与声音律动闪断。
- 处置：**Rust 壳轮询状态机必须区分"暂无数据"与"明确禁用"**。

**[P2] ui/src/Studio.tsx:112-137 — 暂停会话被实时预览静默销毁**（已复核确认）
- 预览防抖的排除列表含 game/agent/trigger 模式但漏了 `paused`；`preview` op（server/main.mjs:707-722）无条件清空 `suspendedScene/pendingSceneRestore`。暂停→编辑颜色→暂停丢失、无法续播。跨平台 UI 代码。

**[P2] server/codex.mjs:297-310 — 未决审批请求把 active 状态改写为 needsInput**（需运行验证）
- 依赖响应事件 id 与请求 `call_id/request_id` 匹配；不匹配时整个 turn 恒报"等待回答"，300 秒后翻成 unknown，且偏向最旧请求。取决于 Codex rollout 事件真实字段。

**[P2] server/claude-sessions.mjs:134-140 — `claude --resume` 复用 session id 时，尾窗旧事件把活跃会话判死**（高度可疑，需实机验证）
- resume 复用同一 spool 文件；`started > firstEventAt + 5000` 的判死逻辑在 registry 缺条目时把正在工作的会话立即标为"已结束"，直到旧事件滚出 400 条尾窗。`claude-actions.mjs:100` 恰恰引导用户用 resume。

## 3. 处置建议（与移植计划对齐）

**M0 顺带修（测试夹具，阻塞回归网）**：§1 两项夹具修复 + `claude-events.mjs:37` / `claude-actions.mjs:144` 的路径前缀判断（平台门控）。

**Rust 重写时的设计约束（勿复制模式）**：P1-1 stdout EOF 终止语义、P1-2 进程存活部分成功处理、P2-2 轮询失败≠禁用、P3-20 stdin 限长读取、P3-21 钩子 keyUp 边界、P3-23/24 音频资源与设备缓存模式。

**需实机（macOS 真机）验证后定级**：P1-2 的 ps 退出码行为、P2-4 Codex 审批事件字段、P2-5 resume 会话复现、P3-3 keyRestoreFailed 清除路径、P3-16 procStart 格式。**不阻塞 Windows 移植开工。**

**已排查确认无问题的高危面**（供移植对照）：HTTP token/Host/Origin/路径穿越防线完整；S4 帧编解码与 D8/B3 边界正确；keyMonitor/triggerMonitor 谓词互斥；frame-loop 停止竞态不存在；storage 原子写在 Windows（MOVEFILE_REPLACE_EXISTING）成立；颜色/动画/音频数学经实测（2M 颜色往返、5000 点动画 fuzz、静音长跑）无缺陷。
